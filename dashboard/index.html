How the radar works

Every number below is measured from the snapshot at run time by the program that built this page (lib/model.ts: measureMultiples scores the market, scoreProtocol scores every row the same way). No protocol name is hardcoded anywhere in the model.

The formula

implied = TVL × category multiple × growth × maturity × chain

  • Category multiple. A category gets its own multiple only when at least 3 live protocols in it trade: the median mcap/TVL ratio of its live protocols, shrunk toward the global median with a prior of 3: (n × median + 3 × global) / (n + 3), clamped to [0.02, 1.0]. A category with fewer than 3 live protocols — or none — takes the global median instead: one or two comparables are not enough evidence for a multiple of their own, so a single small protocol cannot set the value of a whole category.
  • Growth. 7-day TVL change, clamped to [−50%, +100%]; multiplier 1 + (growth / 100) × 0.5.
  • Maturity. Days from listed_at to the snapshot date (365 when unknown); multiplier 0.6 + min(age, 1095) / 1095 × 0.4.
  • Chains. 1 + min(chains − 1, 4) × 0.02, at most 1.08.

Read this honestly

  • The board says a protocol records no token, never that it has none: DefiLlama’s record is not proof, and a protocol on the board may still have a token its record does not carry.
  • The implied value is our model’s claim, not a prediction or a promise that a token will launch, or at any price.
  • Live-token protocols are kept apart from the board on purpose: the board ranks what has not launched yet, and the Live tab shows the market values the multiples are measured from.
